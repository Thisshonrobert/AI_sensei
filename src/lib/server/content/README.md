# Content and import boundary

`canonical-import.mjs` owns phase-1 validation, bounded inventory/duplicate previews, exact-payload approval and one transactional promotion path under Master Plan §§3–4, 16, 18. Imports preserve raw records, nested examples/source words and question specifications. Source keys are citations, not canonical item identities. The optional explicit `reviewBasis` distinguishes source comparison from user acceptance without PDF comparison. Exact approval includes separate supplementary-content decisions and citations; unresolved additions stay draft. Repeated promotion preserves records and batch commit metadata.

Stored approval must match the complete record, reviewed decisions, source/edition context and canonical dependencies. JSON verification/status flags alone cannot approve anything. Corrections append evidence/content and canonical snapshots. Dictionary enrichment requires its own SourceEntry, with field origins referencing the same item. Book imports reject generated/user origin. Unresolved questions remain draft and keep the batch partial. No learner state, cards, FSRS or scored-test selection is implemented.

`catalog.ts` retrieves bounded explicit canonical records for server-rendered pages; `catalog-input.ts` bounds kind, search and pagination. `../db.ts` is server-only. Raw source payloads, file references and approvals are not exposed by these page queries. Exact historical field evidence remains accessible after later source revisions.
