# Content and import boundary

`canonical-import.mjs` owns phase-1 validation, bounded inventory/duplicate previews, exact-payload approval and one transactional promotion path under Master Plan §§3–4, 16, 18. It uses the existing Node/Prisma/Zod tooling; no application runtime or client endpoint is introduced. Imports preserve raw records, nested examples/source words and question specifications. Source keys are citations, not canonical item identities.

Stored approval must match the complete record, reviewed decisions, source/edition context and canonical dependencies. JSON verification/status flags alone cannot approve anything. Corrections append evidence/content and canonical snapshots. Dictionary enrichment requires its own SourceEntry, with field origins referencing the same item. Book imports reject generated/user origin. Unresolved questions remain draft and keep the batch partial. No learner state, cards, FSRS or scored-test selection is implemented.
