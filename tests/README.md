# Verification scope

The grammar display regression checks every one of the ten imported grammar points: its approved generated English explanation is visible near the top, labelled Generated, and the empty book-only explanation field is absent. There are now two production-browser flows.

`import-batches.test.mjs` uses Node's built-in test runner for staging sanitation trust-boundary checks. Real database load/reload evidence belongs in docs/tooling_Verification.md. `catalog-queries.test.mjs` checks bounded route/search/paging inputs. No scheduled study/resume behavior exists yet. See Master Plan §18 for full phase gates.

`canonical-import.test.mjs` checks hash/identity/selection boundaries. `canonical-postgres.test.mjs` verifies typed/provenance constraints, promotion approval/invalidation, repeat/correction no-ops, real SQL rollback, multiple-source kanji reuse, vocabulary/grammar distinctions, partial batches and draft-question exclusion. Run `rtk bun run test:canonical` for these integration checks. `rtk bun run test` skips them unless the isolated runner supplies `CANONICAL_TEST_URL`; do not set that to the staging database.

Canonical checks additionally cover explicit acceptance with unknown edition, separate dictionary/generated additions, shared citations, immutable supplement corrections, omitted/restored citations, question parents, uncertainty rejection and unchanged commit timestamps. `tests/browser/catalog.spec.ts` checks the real reference library in installed Edge: exact source navigation and refresh, origin/acceptance/draft labels, keyboard skip focus, mobile wrapping, empty/malformed queries, invalid IDs and inaccessible private JSON. Run `rtk bun run build` then `rtk bun run test:browser`; port 3000 must be free. No traces/screenshots of real source text are retained by the test configuration.
